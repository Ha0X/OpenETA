# Tool contact contract

These are current scoped tool contracts, not additional robot capabilities. Live schemas and receipts take precedence.

For intentional pushing with a held tool, use a separate single-arm `move_to` with `tool_contact={"mode":"stroke","surface_mark":"fresh_table_mark","target_marks":["fresh_workpiece_mark", "fresh_receiver_mark"]}`. For sliding the held tool along the table before reaching any workpiece, use target_marks=[]; this authorizes only the held tool/table contact and keeps all other object collisions checked. Mark bodies intended to contact the tool or one another when interaction is needed; include a receiving body when needed. All marks must come from the current images. This permits contact only among the held tool, those explicitly marked bodies, and the local table patch. It never authorizes fingers, wrist, camera or arm to contact workpieces. Each stroke is at most 5 cm, preserves orientation, changes height by at most 3 mm, and has no waypoints. All involved geometry must stay within the authorized radius of the table mark (20 cm by default). Both contact modes accept an explicit `patch_radius_m` from 0.05 to 0.35 m when a broad tool hides the table beneath it; use the smallest region that fits the visible geometry and intended short motion. An oversized footprint rejection reports the required radius, without expanding authorization automatically. The Host limits motion increments and checks a 3 mm path envelope, 0.01 rad orientation envelope, live grasp evidence, and at most 1 mm actual penetration at every physics step. Target objects can move under native physics; their future motion is not guaranteed. Inspect the updated images after every short stroke and choose the next action. Do not use ordinary free-space moves to push through a collision stop.

For small three-dimensional contact adjustments, use `tool_contact.mode="adjust"` with the same explicit surface/workpiece selection. It permits changing height, angle, or both; `reorient` remains an equivalent alias. This differs from a nearly horizontal, constant-orientation `stroke`. Supply your chosen target pose: at most 3 cm TCP translation and 15 degrees rotation, one target, no waypoints or batch. The TCP stays within 3 mm of the requested line segment and the orientation within 0.01 rad of the shortest commanded rotation arc; translation and rotation are not guaranteed to share the same progress fraction. This is not a fixed object pivot or a promise that support persists. `point_in_tcp` may express the endpoint using your measured point, but it constrains that point only at the endpoint. Grasp evidence, relative-motion stops, per-physics-step contact bounds, the 1 mm penetration limit and all non-authorized collisions remain checked. The Host does not select a height or angle, infer a tool function, or adjust object poses. This configured adapter supports rigid-body objects; do not assume that visually flexible-looking tool parts will bend. Choose heights and orientations from the current RGB-D geometry, and inspect contact results instead of assuming a level path over every contacted surface. Remeasure after the movement; renew stationary support separately if needed.

A tool-stroke receipt can return `workpiece_references`, keyed to the input `target_marks` indices. To contact one of those same bodies again, including a separating stroke when it is occluded, explicitly pass its handle in `target_handles` (with `target_marks: []` if no new points are needed). At most eight marks and handles may be selected together. A handle remembers identity, not current pose or grasp success, and grants no contact until included in a new stroke. It is restricted to the same episode, role and grasp authorization; measured release or grasp reauthorization invalidates it. The table mark must still be fresh, and all live attachment, patch, path and penetration checks still apply. Do not guess hidden pixels or handles; reacquire a visible point if a reference expires.

In `workpiece_contact`, `near_interaction_pairs` separates tool/workpiece and workpiece/workpiece geometry from `near_workpiece_table_pairs`. Each list contains at most four distinct body pairs within the reported 2 mm computed-distance band. `workpiece_reference_indices` refers to the same receipt's `workpiece_references`, so you can relate a pair to your explicit selections. Inspect the distance method: a conservative separation bound can overstate proximity, and these lists do not measure contact force or prove contact. They reuse the current measured collision geometry, provide no object pose, and do not establish which interaction caused slip. The original `limiting_pairs` still reports the globally most limiting geometry pairs.

A stroke's contact authorization ends with that call. To keep its tool resting on the table while the other arm moves, renew stationary support explicitly with a fresh table mark and a `support_contact` placement at the current TCP position with `retain_support=true`.

For a visible tool working point, `mark_point(..., relative_to_tcp="right")` (or another configured role) also returns `tcp_point.point_in_tcp`, computed only from the public RGB-D point and current robot TCP pose. This expresses coordinates, not object identity or attachment. To target that hand-frame point rather than the TCP origin, explicitly put `point_in_tcp` in a move target alongside the desired world `xyz`; the Host solves `tcp_xyz = xyz - target_rotation @ point_in_tcp` and reports `explicit_tcp_point_target_conversion`. Orientation axes still describe the TCP. Each waypoint must explicitly include its own offset or targets the TCP origin as usual. A measured point on a held tool is only approximately fixed to the hand: remeasure after slip, release, regrasp or uncertain contact, and inspect the actual working surface after motion. The helper grants no contact, does not track objects, and does not establish that the physical point reached its goal. All existing movement and contact bounds apply to the converted TCP trajectory.

Plan the path of the tool's visible working surface, which can be offset from the grasp TCP. Check its height, facing direction and overlap with the workpiece from the images and depth marks. After a stroke, compare the visible workpiece motion with the intended effect. Reaching the TCP target with a steady grip does not establish effective contact. If the tool travels but the workpiece barely moves or stays at a receiver edge, reassess the working face, lateral alignment and approach height before repeating a similar stroke. Any orientation change needs a separate checked motion with suitable clearance.
